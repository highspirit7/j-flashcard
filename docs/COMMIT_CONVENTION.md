# 커밋 메시지 규칙

이 프로젝트에서는 커밋 메시지에 Conventional Commits 형식을 사용합니다.
`type`과 같은 prefix는 영어로 통일하고, 메시지 내용은 일본어로 작성합니다.

## 기본 형식

```text
<type>: <日本語の要約>
```

예시:

```text
feat: 学習カードの裏面表示を追加
fix: 復習日の計算結果が保存されない問題を修正
```

## type 종류

| type       | 용도                                         |
| ---------- | -------------------------------------------- |
| `feat`     | 새로운 기능 추가                             |
| `fix`      | 버그 수정                                    |
| `docs`     | 문서 변경                                    |
| `style`    | 동작에 영향을 주지 않는 서식이나 스타일 변경 |
| `refactor` | 동작을 변경하지 않는 코드 구조 개선          |
| `test`     | 테스트 추가 및 수정                          |
| `chore`    | 의존성이나 설정 등 기타 작업                 |
| `perf`     | 성능 개선                                    |
| `build`    | 빌드 시스템이나 외부 의존성 변경             |
| `ci`       | CI/CD 설정 변경                              |
| `revert`   | 이전 커밋 되돌리기                           |

## 작성 규칙

- prefix와 요약 사이에는 `: `를 입력합니다.
- 요약은 일본어로 작성하며, 변경 내용을 간결하게 표현합니다.
- 요약 마지막에는 마침표(`。`)를 붙이지 않습니다.
- 요약은 원칙적으로 50자 이내를 기준으로 합니다.
- 하나의 커밋에는 서로 관련된 변경만 포함합니다.
- 변경 규모가 큰 경우 필요에 따라 본문을 추가해 배경이나 이유를 설명합니다.

## 본문을 포함하는 형식

```text
<type>: <日本語の要約>

<변경 배경이나 구현 내용을 일본어로 설명>
```

예시:

```text
refactor: カード情報の取得処理を分離

デッキ一覧と学習画面で同じ取得処理を利用できるように、
カード取得用の関数を専用モジュールへ移動
```

## 피해야 할 예시

```text
update
fix stuff
feat: add feature
```

prefix가 없거나, 내용이 모호하거나, 일본어로 내용을 전달하지 않는 메시지는 피합니다.

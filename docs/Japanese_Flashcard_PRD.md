> **프로젝트 명:** J-Flashcard (가칭)  
> **문서 버전:** v1.0  
> **작성자:** 이지열
> **최종 수정일:** 2026-08-15

## 1. 프로젝트 개요 & 목적 (Overview & Goals)

### 1.1 배경 및 목적

- **배경:** 일본어 공부를 시작하면서, 사용하기 시작한 단어장 앱에 아쉬운 점이 있어서 그런 아쉬운 점들을 보완한 단어장 앱을 제작하고자 합니다. Anki 단어장의 경우, deck 내에서 특정 단어를 삭제하는 기능이 없었습니다. 그리고 특히 초보자의 경우 예문을 입력하기도 어렵고, 단어 뜻부터 한자 발음이 어떻게 되는지 찾는 것도 약간의 시간이 걸리는 일이기에 AI를 활용해서 빠르게 입력하는 기능의 필요성을 느꼈습니다.
- **목적:**
  - **FSRS 기반 복습:** `Again`, `Hard`, `Good`, `Easy` 4단계 평가를 바탕으로 카드별 기억 안정성과 난이도를 반영한 복습 주기 제공.

### 1.2 핵심 성공 지표

- 로그인/로그아웃 기능 정상 작동 (사전에 생성한 인증 정보로 세션 관리).
- Anki 4단계 평가 버튼 선택 시, FSRS가 카드 상태에 맞는 복습 주기와 다음 복습일(`dueDate`)을 정상 계산 및 반영.
- 백엔드 DB 연동을 통한 데이터 로딩 및 멀티 디바이스 연속 학습 지원.

## 2. 사용자 페르소나 및 학습 시나리오 (User Persona & Scenarios)

### 2.1 타겟 페르소나

- **성함:** 본인 (개발 경력이 있는 일본어 초급 학습자)
- **주요 사용 환경:** 모바일 브라우저 (지하철, 이동 중) 및 데스크톱 브라우저 (공부 책상)
- **니즈:**
  - 단어, 읽기, 뜻, 예문을 직접 관리할 수 있는 간결한 단어 등록 경험.
  - 단순 암기 확인을 넘어 **FSRS 기반 4단계 복습 시스템**으로 효율적 학습.
  - PC와 모바일 어디서 접속하든 나의 학습 기록과 단어장이 백엔드 DB를 통해 항상 동기화.
  - 빠른 UI 반응 속도 및 즉각적인 인터랙션 제공.

### 2.2 대표 시나리오

1. **단어 등록:** 새로 배운 단어(예: `食べる`)의 읽기(`たべる`), 품사(`동사`), 뜻(`먹다`), 예문(`昼ご飯を食べる` / `점심을 먹는다`)을 입력하고 저장한다.
2. **덱 상세 확인:** 홈 화면에서 'JLPT N5 - 필수 동사' 덱 이름을 클릭하여 덱 상세·단어 관리 화면으로 이동한다.
3. **학습 모드 실행:** 덱 상세·단어 관리 화면에서 '학습 시작'을 선택하여 플래시카드 학습을 시작한다.
4. **카드 확인 및 Anki 평가:**
   - 카드 앞면의 단어(`食べる`)를 보고 발음/뜻을 생각한 뒤 터치하여 뒷면을 확인한다.
   - 뒷면에는 읽기(`たべる`), 품사(`동사`), 뜻(`먹다`), 예문이 표시된다.
   - 카드 하단의 4개 평가 버튼과 상단에 표시된 예상 복습 간격을 확인한다.
     - 전혀 기억나지 않음 ➔ **`Again` (<1분)** 선택 (세션 내 재학습)
     - 어렵게 떠올림(한자로 된 단어의 경우 뜻은 아는데 발음은 모르는 경우도 포함) ➔ **`Hard` (<10분)** 선택
     - 무난하게 맞춤 ➔ **`Good` (1일)** 선택
     - 아주 쉽게 맞춤 ➔ **`Easy` (4일)** 선택
5. **자동 스케줄링 & 저장:** 선택한 평가에 따라 FSRS 스케줄러가 다음 복습일(`dueDate`)을 계산한다. 해당 데이터는 **백엔드 DB에 저장**된다.

## 4. 데이터 모델 개요 (Data Model Overview)

J-Flashcard는 Supabase Auth와 다음 애플리케이션 데이터를 사용한다.

- **사용자:** Supabase `auth.users`에서 관리한다. 애플리케이션의 별도 사용자 테이블은 만들지 않는다.
- **덱:** 사용자가 소유하는 단어 묶음이다.
- **카드:** 덱에 포함되는 일본어 단어와 FSRS 학습 상태다.
- **예문:** 카드에 연결되는 일본어 예문과 한국어 뜻이다. 예문 읽기는 선택값이다.
- **복습 로그:** 카드 평가 결과의 변경 이력이다.

주요 관계는 다음과 같다.

- 한 사용자는 여러 덱을 소유한다.
- 한 덱은 여러 카드를 가진다.
- 한 카드는 여러 예문을 가진다.
- 한 카드는 여러 복습 로그를 가진다.
- 카드를 삭제해도 복습 로그는 보존한다.

카드와 예문은 덱 안에 중첩된 JSON 데이터가 아니라 별도 테이블로 관리한다. 구체적인 테이블, 컬럼, 타입, 필수 여부, 제약 조건, 접근 정책은 [데이터仕様書](DATA_SPECIFICATION.md)를 따른다.

## 5. UI/UX 화면 구조 및 흐름 (User Interface & Flow)

### 5.1 화면 구조 (Screens)

1. **로그인 화면 (Login Screen)**
   - 사용자명, 비밀번호 입력 필드
   - 로그인 버튼
2. **홈 화면 (Deck List Screen)**
   - 전체 덱 목록 카드 노출 (오늘 학습 예정 카드 수: New/Learning/Review 구분)
   - 덱 이름 클릭 시 해당 덱의 상세·단어 관리 화면으로 이동
   - '새 덱 추가' 버튼
   - '새 덱 추가' 버튼 클릭 시 덱 생성 모달 표시
   - 모달에서 덱 이름, 설명을 입력하고 저장 또는 취소
   - 상단 오른쪽: 현재 사용자 정보 및 로그아웃 버튼
3. **덱 상세 / 단어 관리 화면 (Deck Detail & Word List Screen)**
   - 단어 리스트 표시
   - 각 단어 행에 편집/삭제 버튼
   - '새 카드 추가' 버튼
   - '학습 시작' 대형 버튼
   - 덱 자체를 삭제하는 버튼 (삭제 전 확인 필요, 홈 화면 목록에는 노출하지 않음)
4. **단어 생성 페이지 (Word Create Page)**
   - 단어(일본어 표기), 읽기(Reading), 뜻(Meaning), 품사(Part of Speech) 입력 가능
   - 예문 리스트 입력 영역 (각 예문과 해당 한글 뜻을 개별적으로 추가/삭제/수정 가능)
   - 저장 및 취소 버튼
5. **단어 편집 페이지 (Word Edit Page)**
   - 기존 카드 정보를 모두 불러와 수정 가능
   - 단어, 읽기, 뜻, 품사, 예문 리스트 전체 수정 가능
   - 변경 사항 감지 시 저장 버튼 활성화
   - 저장 및 취소 버튼
6. **학습 화면 (Flashcard Screen)**
   - 상단: 진행도 프로그레스 바 및 해당 덱의 남은 카드 수
   - 중앙: 플래시카드 (터치/클릭 시 3D Flip 애니메이션)
   - 하단: **Anki 4단계 평가 버튼 (`Again`, `Hard`, `Good`, `Easy`)** + 예상 복습 주기 텍스트

### 5.2 주요 동작 흐름 (Workflows)

#### 덱 생성 워크플로우

1. 사용자가 홈 화면에서 '새 덱 추가' 버튼 클릭
2. 덱 생성 모달 표시
3. 사용자가 덱 이름, 설명 입력
4. 저장 버튼 클릭
5. 입력값 검증
6. 검증에 성공하면 Supabase DB에 새 덱 저장
7. 모달 닫기
8. 홈 화면의 덱 목록에 새 덱 표시

- 취소 버튼을 클릭하면 입력 내용을 저장하지 않고 모달을 닫는다.
- 저장 중에는 중복 제출을 방지한다.
- 저장에 실패하면 모달을 닫지 않고 오류 메시지를 표시한다.

#### 단어 생성 워크플로우

1. 사용자가 덱 상세 화면에서 '새 카드 추가' 버튼 클릭
2. 단어 생성 페이지로 이동
3. 사용자가 단어, 읽기, 뜻, 품사, 예문 정보를 입력
4. 저장 버튼 클릭
5. Supabase DB에 새 카드 저장
6. 덱 상세 화면으로 돌아가기

#### 단어 편집 워크플로우

1. 사용자가 덱 상세 화면에서 단어 행의 편집 버튼 클릭
2. 단어 편집 페이지로 이동 (현재 정보 미리 로드)
3. 사용자가 필드 수정 (예: 뜻 변경)
4. 저장 버튼 클릭
5. 백엔드가 변경 사항을 저장한다. 어떤 필드가 바뀌든 카드의 학습 상태(`state`)와 FSRS 스케줄링 값은 변경하지 않는다. 뜻이 바뀌어 기존 기억과 맞지 않게 되어도, 다음 복습에서 사용자가 낮은 평가를 선택하면 FSRS가 정상적인 복습 흐름으로 상태를 재조정한다.
6. 백엔드 DB에 변경 사항 저장
7. 덱 상세 화면으로 돌아가기

## 6. 비기능적 요구사항 (Non-Functional Requirements)

- **성능 및 응답성:** 카드 뒤집기 애니메이션은 60fps로 부드럽게 동작하며, 백엔드 DB와의 효율적인 데이터 통신으로 빠른 응답 제공.
- **접근성 및 반응형:** 모바일 화면(폭 360px 이상)부터 데스크톱 화면까지 레이아웃 파손 없이 대응.

## 7. 기능별 완료 조건 (Acceptance Criteria)

각 기능은 아래 조건을 모두 만족할 때 완료된 것으로 판단한다.

### 7.1 사용자 인증

- 올바른 인증 정보로 로그인할 수 있다.
- 잘못된 인증 정보를 입력하면 로그인되지 않고 오류 메시지가 표시된다.
- 로그인한 사용자는 새로고침 후에도 유효한 세션을 유지한다.
- 로그인하지 않은 사용자가 보호된 화면에 접근하면 로그인 화면으로 이동한다.
- 로그아웃하면 세션이 종료되고 로그인 화면으로 이동한다.

### 7.2 덱 관리

- 로그인한 사용자의 덱 목록만 표시된다.
- '새 덱 추가' 버튼을 클릭하면 덱 생성 모달이 표시된다.
- 새 덱을 생성하면 이름과 설명이 저장되고 목록에 표시된다.
- 덱 생성 모달에서 저장하지 않고 닫으면 덱이 생성되지 않는다.
- 덱의 이름과 설명을 수정할 수 있다.
- 덱을 삭제하기 전에 삭제 여부를 확인할 수 있다.
- 덱을 삭제하면 해당 덱이 목록에서 사라지고 다시 조회해도 표시되지 않는다.
- 덱을 삭제하면 덱에 포함된 카드도 함께 삭제된다. 카드의 학습 기록(복습 로그)은 삭제하지 않고 보존한다.
- 덱 목록을 불러오는 중이거나 불러오기에 실패한 경우 사용자가 현재 상태를 알 수 있다.

### 7.3 카드 관리

- 카드 생성 시 일본어 표기, 읽기, 뜻, 품사를 입력할 수 있다.
- 예문을 하나 이상 추가하고 각 예문의 일본어 문장, 읽기, 한국어 뜻을 입력할 수 있다.
- 필수 입력값이 누락되면 저장되지 않고 해당 필드의 오류가 표시된다.
- 저장한 카드는 해당 덱의 카드 목록에 표시된다.
- 기존 카드의 내용과 예문을 수정할 수 있다.
- 카드 삭제 전에 삭제 여부를 확인할 수 있다.
- 카드 삭제 후 목록과 데이터베이스에서 해당 카드가 사라진다.
- 카드를 삭제해도 해당 카드의 학습 기록(복습 로그)은 덱 삭제와 동일하게 삭제하지 않고 보존된다.
- 카드 내용을 수정해도 학습 상태(`state`)와 FSRS 스케줄링 값(`stability`, `difficulty`, `interval`, `due_date` 등)은 변경되지 않는다.

### 7.4 학습 모드

- 덱에서 학습을 시작하면 학습 대상 카드가 표시된다.
- 카드 앞면에는 일본어 표기가 표시된다.
- 카드를 터치하거나 클릭하면 뒷면으로 전환된다.
- 뒷면에는 읽기, 품사, 뜻, 예문이 표시된다.
- 현재 진행률과 남은 카드 수가 표시된다.
- 학습할 카드가 없으면 빈 상태 또는 학습 완료 상태가 표시된다.
- 모바일 화면과 데스크톱 화면에서 카드와 평가 버튼이 겹치지 않는다.

### 7.5 학습 평가 및 FSRS 스케줄링

- 카드 뒷면을 확인한 후 `Again`, `Hard`, `Good`, `Easy` 평가 버튼을 사용할 수 있다.
- 카드 뒷면을 확인하기 전에는 평가 버튼을 사용할 수 없다.
- 각 평가 버튼에 해당하는 예상 복습 간격이 표시된다.
- 평가를 선택하면 FSRS가 카드의 상태, 안정성, 난이도, 복습 간격, 다음 복습일을 계산한다.
- 계산된 학습 결과가 해당 카드에 저장된다.
- `Again` 선택 시 카드가 필요한 경우 현재 학습 세션에 다시 표시된다.
- 평가 저장이 실패하면 사용자에게 오류를 알리고 재시도할 수 있다.
- 평가 저장 후 다음 학습 카드 또는 학습 완료 상태가 표시된다.

### 7.6 데이터 저장 및 동기화

- 덱, 카드, 예문, 학습 결과를 Supabase 데이터베이스에 저장할 수 있다.
- 화면을 새로고침해도 저장된 데이터가 유지된다.
- 같은 사용자로 다른 기기에서 로그인하면 저장된 덱, 카드, 학습 상태를 조회할 수 있다.
- 사용자는 자신의 데이터만 조회하고 수정하고 삭제할 수 있다.
- 데이터 조회 또는 저장에 실패하면 오류 상태가 표시되고 기존 화면이 임의로 성공 상태로 바뀌지 않는다.

# API 명세서 (데이터 접근 명세)

> **프로젝트:** J-Flashcard  
> **문서 버전:** v1.0  
> **대상:** Supabase Auth / Supabase를 통한 PostgreSQL  
> **관련 문서:** [PRD](Japanese_Flashcard_PRD.md), [데이터 명세서](DATA_SPECIFICATION.md), [화면 명세서](screen-specifications/README.md)

## 1. 문서의 목적

이 문서는 J-Flashcard 화면에서 Supabase에 접근하는 기능 단위의 계약을 정의한다.

이 프로젝트에는 별도의 독립 API 서버가 없다. 웹·모바일 클라이언트의 공통 서버 진입점이 필요한 기능은 Supabase Edge Function으로 제공하고, 데이터 변경의 원자성이 필요한 작업은 Edge Function이 호출하는 Supabase RPC에서 처리한다. 따라서 `GET /api/...`와 같은 독립 서버의 HTTP 엔드포인트가 아니라, Supabase Auth·Edge Function·RPC·테이블 조작을 사용자 기능 단위로 기술한다.

구현 시 DB 컬럼, 타입, 제약 조건은 [DATA_SPECIFICATION.md](DATA_SPECIFICATION.md)를 기준으로 한다. DB 접근은 항상 로그인한 사용자의 세션을 사용하며, RLS를 활성화한 상태에서 수행한다.

## 2. 공통 사양

### 2.1 인증

- 대상 작업은 원칙적으로 유효한 Supabase Auth 세션을 필요로 한다.
- 현재 사용자 ID에는 세션의 `user.id`를 사용한다.
- `user_id`를 화면 입력값으로 신뢰하지 않고 인증 세션에서 가져온다.
- 인증되지 않았거나 세션이 만료된 경우 보호된 화면의 데이터 조회·갱신을 실행하지 않는다.

### 2.2 데이터 형식

- ID에는 UUID를 사용한다.
- 날짜와 시간에는 PostgreSQL의 `timestamptz`를 사용하고, 애플리케이션에서는 ISO 8601 형식의 문자열로 취급한다.
- DB 컬럼명에는 snake_case를 사용한다.
- Supabase 응답 오류의 내부 정보를 그대로 화면에 표시하지 않고, 사용자가 다음에 취할 행동을 알 수 있는 메시지로 변환한다.

### 2.3 공통 처리 결과

| 결과          | 처리                                                     |
| ------------- | -------------------------------------------------------- |
| 성공          | 조회·저장한 데이터를 화면 상태에 반영한다.               |
| 입력 오류     | DB 접근을 실행하지 않고 해당 필드에 오류를 표시한다.     |
| 인증되지 않음 | 로그인 화면으로 이동한다.                                |
| 통신·DB 오류  | 성공 상태로 변경하지 않고 재시도 가능한 오류를 표시한다. |

## 3. 인증 API

### 3.1 로그인

| 항목          | 내용                                          |
| ------------- | --------------------------------------------- |
| Supabase 작업 | `auth.signInWithPassword`                     |
| 입력          | `email`, `password`                           |
| 전제 조건     | email과 password가 비어 있지 않아야 한다.     |
| 성공          | 세션을 유지하고 홈·덱 목록 화면으로 이동한다. |
| 실패          | 로그인 화면에 인증 오류를 표시한다.           |

### 3.2 세션 확인

| 항목          | 내용                                                           |
| ------------- | -------------------------------------------------------------- |
| Supabase 작업 | `auth.getSession` / `auth.onAuthStateChange`                   |
| 성공          | 현재 사용자 정보를 애플리케이션 상태에 반영한다.               |
| 세션 없음     | 인증되지 않은 상태로 처리하고 보호된 화면에 접근시키지 않는다. |

### 3.3 로그아웃

| 항목          | 내용                                                                 |
| ------------- | -------------------------------------------------------------------- |
| Supabase 작업 | `auth.signOut`                                                       |
| 성공          | 로컬 사용자 상태를 폐기하고 로그인 화면으로 이동한다.                |
| 실패          | 현재 화면을 성공 상태로 변경하지 않고 재시도 가능한 오류를 표시한다. |

## 4. 덱 API

### 4.1 덱 목록 조회

| 항목          | 내용                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| Supabase 작업 | 덱 목록 조회와 카드 수 집계를 처리하는 Supabase Edge Function 호출. 카드 수 집계는 내부 RPC에서 수행한다. |
| 조건          | 현재 사용자가 소유한 덱만 조회한다.                                                                       |
| 주요 데이터   | `id`, `title`, `description`, `created_at`, `updated_at`                                                  |
| 추가 표시     | 덱별 카드 수, New/Learning/Review 수                                                                      |
| 성공          | 홈·덱 목록 화면에 목록을 표시한다.                                                                        |
| 빈 결과       | 오류가 아니라 덱 생성을 유도하는 빈 상태를 표시한다.                                                      |

카드 수를 조회할 때도 현재 사용자가 소유한 덱에 속한 카드만 대상으로 한다. 카드 수와 New/Learning/Review 수는 RPC에서 집계하며, 클라이언트에서 카드 전체 목록을 가져와 집계하지 않는다.

### 4.2 덱 생성

| 항목          | 내용                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| Supabase 작업 | `from('decks').insert(...).select().single()`                                                                  |
| 입력          | `title`, `description?`                                                                                        |
| 자동 설정     | `user_id`에는 현재 세션의 사용자 ID를 설정한다.                                                                |
| 검증          | `title`은 빈 문자열을 허용하지 않으며 중복을 허용한다. `description`은 선택 사항이고 최대 문자 수 제한은 없다. |
| 성공          | 생성한 덱을 목록에 반영한다.                                                                                   |
| 실패          | 입력값을 유지하고 생성 실패를 표시한다.                                                                        |

### 4.3 덱 수정

| 항목          | 내용                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Supabase 작업 | `from('decks').update(...).eq('id', deckId).select().single()`                                                         |
| 입력          | `deckId`, `title`, `description?`                                                                                      |
| 검증          | `title`은 빈 문자열을 허용하지 않으며 중복을 허용한다. 대상 덱은 현재 사용자가 소유해야 하고 최대 문자 수 제한은 없다. |
| 성공          | 수정된 덱 정보를 화면에 반영한다.                                                                                      |
| 실패          | 입력값과 기존 덱 정보를 유지하고 저장 실패 메시지를 표시하며, 성공 상태로 변경하지 않는다.                             |

### 4.4 덱 삭제

| 항목          | 내용                                                                |
| ------------- | ------------------------------------------------------------------- |
| Supabase 작업 | `from('decks').delete().eq('id', deckId)`                           |
| 전제 조건     | 화면에서 삭제 확인을 완료해야 한다.                                 |
| 성공          | 덱을 목록에서 제외하고 홈 화면으로 이동한다.                        |
| DB 동작       | 하위 카드와 예문은 cascade 삭제된다. 관련 `review_logs`는 유지된다. |
| 실패          | 덱을 화면에서 제외하지 않고 삭제 실패를 표시한다.                   |

## 5. 카드·예문 API

### 5.1 카드 목록 조회

| 항목          | 내용                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| Supabase 작업 | 카드 목록 조회를 처리하는 Supabase Edge Function 호출                                                       |
| 조건          | 대상 덱을 현재 사용자가 소유해야 한다.                                                                      |
| 주요 데이터   | `id`, `deck_id`, `word`, `reading`, `meaning`, `part_of_speech`, `state`, `due`, `created_at`, `updated_at` |
| 성공          | 덱 상세·단어 관리 화면에 카드 목록을 표시한다.                                                              |
| 빈 결과       | 오류가 아니라 새 카드 생성을 유도하는 빈 상태를 표시한다.                                                   |
| 실패          | 카드 목록을 성공 상태로 표시하지 않고 오류 메시지와 재시도 동작을 표시한다.                                 |

카드가 10개를 초과하는 경우 페이지네이션을 적용한다.

### 5.2 카드 생성

| 항목          | 내용                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| Supabase 작업 | `from('cards').insert(...).select().single()`                                        |
| 입력          | `deck_id`, `word`, `reading?`, `meaning`, `part_of_speech`                           |
| 자동 설정     | FSRS 관련 필드에는 DB의 기본값을 사용한다.                                           |
| 검증          | `deck_id`, `word`, `meaning`, `part_of_speech`는 필수이고 `reading`은 선택 사항이다. |
| 성공          | 생성한 카드를 덱의 카드 목록에 반영한다.                                             |
| 실패          | 입력값을 유지하고 저장 실패 메시지를 표시하며, 카드를 목록에 추가하지 않는다.        |

카드를 생성한 후 예문이 있으면 카드 ID를 사용해 예문을 추가한다. 카드 생성에 실패한 경우 예문 저장을 시작하지 않는다.

### 5.3 카드 수정

| 항목          | 내용                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Supabase 작업 | `from('cards').update(...).eq('id', cardId).select().single()`                                                                        |
| 입력          | `cardId`, `word`, `reading?`, `meaning`, `part_of_speech`                                                                             |
| 성공          | 카드 내용과 예문 변경 사항을 반영한다.                                                                                                |
| 중요한 제약   | 카드 내용을 수정할 때 `state`, `stability`, `difficulty`, `scheduled_days`, `reps`, `lapses`, `due`, `last_review`는 변경하지 않는다. |
| 실패          | 입력값과 예문 변경 사항을 유지하고 저장 실패 메시지와 재시도 방법을 표시한다. 카드 내용이나 학습 상태를 성공 상태로 변경하지 않는다.  |

### 5.4 카드 삭제

| 항목          | 내용                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------- |
| Supabase 작업 | `from('cards').delete().eq('id', cardId)`                                                      |
| 전제 조건     | 화면에서 삭제 확인을 완료해야 한다.                                                            |
| 성공          | 카드와 예문을 목록에서 제외한다.                                                               |
| DB 동작       | 카드에 속한 예문은 cascade 삭제된다. `review_logs.card_id`는 `null`이 되고 로그 행은 유지된다. |
| 실패          | 카드를 목록에서 제외하지 않고 삭제 실패를 표시한다.                                            |

### 5.5 예문 조회·생성·수정·삭제

| 작업 | Supabase 작업                                             | 주요 입력                                              |
| ---- | --------------------------------------------------------- | ------------------------------------------------------ |
| 조회 | `from('card_examples').select(...).eq('card_id', cardId)` | `cardId`                                               |
| 생성 | `from('card_examples').insert(...)`                       | `card_id`, `text`, `reading?`, `meaning`, `sort_order` |
| 수정 | `from('card_examples').update(...).eq('id', exampleId)`   | `exampleId`, 편집 필드                                 |
| 삭제 | `from('card_examples').delete().eq('id', exampleId)`      | `exampleId`                                            |

예문의 `text`와 `meaning`은 필수이고 `reading`은 선택 사항이다. 모든 작업의 소유자 확인은 예문에서 카드와 덱을 추적하는 RLS에 위임한다.

## 6. 학습·리뷰 API

### 6.1 학습 대상 카드 조회

| 항목        | 내용                                                     |
| ----------- | -------------------------------------------------------- |
| 대상        | 지정한 덱에 속한 카드                                    |
| 조건        | 현재 사용자가 소유하며 학습 시점에 복습 대상이어야 한다. |
| 판정        | `state` 및 `due`를 사용한다.                             |
| 조회 데이터 | 카드 내용, FSRS 상태, 예문, 덱 정보                      |
| 성공        | 학습 카드를 세션 큐에 추가한다.                          |
| 빈 결과     | 오류가 아니라 학습 대상 없음 상태를 표시한다.            |

### 6.2 학습 평가 계산

1. 사용자가 카드 뒷면을 확인한다.
2. `again`, `hard`, `good`, `easy` 중 하나를 선택한다.
3. FSRS 스케줄러로 다음 상태를 계산한다.
4. 계산 결과를 카드 수정과 리뷰 기록 저장에 사용한다.

카드 뒷면을 확인하기 전에는 평가 작업을 받지 않는다. 평가를 저장하는 동안 중복 평가를 방지한다.

### 6.3 학습 평가 저장

평가를 저장할 때 카드의 최신 FSRS 상태를 수정하고, 같은 평가 결과를 `review_logs`에 추가한다.

| 작업   | 대상                                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 수정   | `cards.state`, `stability`, `difficulty`, `scheduled_days`, `reps`, `lapses`, `due`, `last_review`                              |
| 추가   | `review_logs.card_id`, `user_id`, `rating`, `state`, `stability`, `difficulty`, `elapsed_days`, `scheduled_days`, `reviewed_at` |
| 입력   | `cardId`, `rating`, FSRS 계산 결과                                                                                              |
| rating | `again` / `hard` / `good` / `easy`                                                                                              |

클라이언트는 학습 평가를 Supabase Edge Function에 전달한다. Edge Function은 FSRS 계산 결과를 검증한 뒤 하나의 Supabase RPC를 호출하고, RPC는 카드 상태 수정과 리뷰 기록 추가를 하나의 트랜잭션으로 실행한다. 두 작업 중 하나라도 실패하면 전체 작업을 롤백하고 화면에서는 평가를 성공으로 처리하지 않으며, 현재 카드를 유지해 재시도할 수 있는 상태로 만든다.

## 7. Row Level Security

RLS는 애플리케이션 화면의 판정을 보조하는 기능이 아니라 DB 접근에 대한 최종 소유자 확인으로 취급한다.

| 테이블          | 접근 조건                                |
| --------------- | ---------------------------------------- |
| `decks`         | `auth.uid() = user_id`                   |
| `cards`         | `deck_id`가 현재 사용자의 덱에 속한다.   |
| `card_examples` | `card_id`가 현재 사용자의 카드에 속한다. |
| `review_logs`   | `auth.uid() = user_id`                   |

`review_logs`에는 insert/delete가 가능하고 update 정책은 두지 않는다. 기존 기록 행을 수정하지 않고 평가마다 새 행을 추가한다.

## 8. 공통 오류 처리 정책

다음 오류 처리 정책을 공통 규칙으로 사용한다.

| 오류 유형                | 사용자 메시지                                    | 처리                                                 |
| ------------------------ | ------------------------------------------------ | ---------------------------------------------------- |
| 인증 실패 또는 세션 만료 | 로그인이 필요합니다.                             | 로그인 화면으로 이동한다.                            |
| 입력 검증 오류           | 해당 필드의 입력 오류 메시지                     | DB 요청을 보내지 않는다.                             |
| 대상 데이터 없음         | 요청한 데이터를 찾을 수 없습니다.                | 해당 데이터의 상위 목록 화면으로 이동한다.           |
| RPC·DB 저장 실패         | 저장하지 못했습니다. 다시 시도해 주세요.         | 입력값과 현재 상태를 유지하고 재시도할 수 있게 한다. |
| 목록 조회 실패           | 데이터를 불러오지 못했습니다.                    | 현재 화면에 오류를 표시하고 재시도를 제공한다.       |
| 네트워크 오류            | 네트워크 연결을 확인하고 다시 시도해 주세요.     | 현재 화면에 오류를 표시하고 재시도를 제공한다.       |
| 알 수 없는 오류          | 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. | 내부 로그를 기록하고 현재 화면에 오류를 표시한다.    |

Supabase, Edge Function, RPC의 내부 오류 코드와 데이터베이스 상세 정보는 사용자 화면에 직접 표시하지 않는다. 오류 메시지 변환은 클라이언트와 Edge Function에서 공통 규칙으로 관리한다.

## 9. 사양과 구현의 갱신 규칙

- DB migration을 변경한 경우 `DATA_SPECIFICATION.md`와 이 문서를 같은 변경 단위로 갱신한다.
- Supabase 작업 방법을 변경한 경우 해당 기능의 ‘Supabase 작업’과 성공·실패 조건을 갱신한다.
- UI 동작만 변경한 경우 해당 화면 명세서를 먼저 갱신하고 데이터 접근 조건에 미치는 영향을 확인한다.
- 구현되지 않은 향후 기능은 이 문서의 확정 사양으로 추가하지 않고 ‘미결정 사항’ 또는 PRD의 대상 외 기능으로 관리한다.

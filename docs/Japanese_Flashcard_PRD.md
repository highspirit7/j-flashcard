> **프로젝트 명:** J-Flashcard (가칭)  
> **문서 버전:** v1.0  
> **작성자:** 이지열
> **최종 수정일:** 2026-08-15

## 1. 프로젝트 개요 & 목적 (Overview & Goals)

### 1.1 배경 및 목적

- **배경:** 일본어 공부를 시작하면서, 사용하기 시작한 단어장 앱에 아쉬운 점이 있어서 그런 아쉬운 점들을 보완한 단어장 앱을 제작하고자 합니다. Anki 단어장의 경우, deck 내에서 특정 단어를 삭제하는 기능이 없었습니다. 그리고 특히 초보자의 경우 예문을 입력하기도 어렵고, 단어 뜻부터 한자 발음이 어떻게 되는지 찾는 것도 약간의 시간이 걸리는 일이기에 AI를 활용해서 빠르게 입력하는 기능의 필요성을 느꼈습니다.
- **목적:**
  - **FSRS 기반 복습:** `Again`, `Hard`, `Good`, `Easy` 4단계 평가를 바탕으로 카드별 기억 안정성과 난이도를 반영한 복습 주기 제공.

### 1.2 핵심 성공 지표

- 로그인/로그아웃 기능 정상 작동 (사전에 생성한 인증 정보로 세션 관리).
- Anki 4단계 평가 버튼 선택 시, FSRS가 카드 상태에 맞는 복습 주기와 다음 복습일(`dueDate`)을 정상 계산 및 반영.
- 백엔드 DB 연동을 통한 데이터 로딩 및 멀티 디바이스 연속 학습 지원.

## 2. 사용자 페르소나 및 학습 시나리오 (User Persona & Scenarios)

### 2.1 타겟 페르소나

- **성함:** 본인 (개발 경력이 있는 일본어 초급 학습자)
- **주요 사용 환경:** 모바일 브라우저 (지하철, 이동 중) 및 데스크톱 브라우저 (공부 책상)
- **니즈:**
  - 단어, 읽기, 뜻, 예문을 직접 관리할 수 있는 간결한 단어 등록 경험.
  - 단순 암기 확인을 넘어 **FSRS 기반 4단계 복습 시스템**으로 효율적 학습.
  - PC와 모바일 어디서 접속하든 나의 학습 기록과 단어장이 백엔드 DB를 통해 항상 동기화.
  - 빠른 UI 반응 속도 및 즉각적인 인터랙션 제공.

### 2.2 대표 시나리오

1. **단어 등록:** 새로 배운 단어(예: `食べる`)의 읽기(`たべる`), 품사(`동사`), 뜻(`먹다`), 예문(`昼ご飯を食べる` / `점심을 먹는다`)을 입력하고 저장한다.
2. **학습 모드 실행:** 'JLPT N5 - 필수 동사' 덱을 선택하여 플래시카드 학습을 시작한다.
3. **카드 확인 및 Anki 평가:**
   - 카드 앞면의 단어(`食べる`)를 보고 발음/뜻을 생각한 뒤 터치하여 뒷면을 확인한다.
   - 뒷면에는 읽기(`たべる`), 품사(`동사`), 뜻(`먹다`), 예문이 표시된다.
   - 카드 하단의 4개 평가 버튼과 상단에 표시된 예상 복습 간격을 확인한다.
     - 전혀 기억나지 않음 ➔ **`Again` (<1분)** 선택 (세션 내 재학습)
     - 어렵게 떠올림(한자로 된 단어의 경우 뜻은 아는데 발음은 모르는 경우도 포함) ➔ **`Hard` (<10분)** 선택
     - 무난하게 맞춤 ➔ **`Good` (1일)** 선택
     - 아주 쉽게 맞춤 ➔ **`Easy` (4일)** 선택
4. **자동 스케줄링 & 저장:** 선택한 평가에 따라 FSRS 스케줄러가 다음 복습일(`dueDate`)을 계산한다. 해당 데이터는 **백엔드 DB에 저장**된다.

## 4. 데이터 모델 설계 (Data Schema)

```typescript
// 사용자 (User) 모델
export interface User {
  id: string; // 고유 ID
  username: string; // 사용자명 (로그인 시 사용)
  passwordHash: string; // 비밀번호 (해시 처리됨)
  createdAt: string; // 생성일
}

// Anki 카드 평가 타입
export type AnkiRating = 'again' | 'hard' | 'good' | 'easy';

// Anki 카드 학습 상태
export type CardState = 'new' | 'learning' | 'review' | 'relearning';

// 카드 (Card) 모델
export interface Card {
  id: string; // UUID 또는 Timestamp 기반 고유 ID
  word: string; // 단어 (일본어 표기: 한자/히라가나/가타가나) (예: 食べる, あります, コンピューター)
  reading?: string; // 후리가나 / 히라가나 읽기 (예: たべる)
  meaning: string; // 한국어 뜻 (예: 먹다)
  partOfSpeech: string; // 품사 (명사, 동사, 형용사, 부사, 조사, 조동사, 연결사, 감동사 등)
  examples: Array<{
    text: string; // 예문 (일본어) (예: 昼飯を食べる)
    meaning: string; // 예문 뜻 (한글) (예: 점심을 먼다)
    reading: string; // 예문 발음
  }>; // 예문 배열 (여러 개 가능)

  // --- FSRS Scheduling Engine Fields ---
  state: CardState; // 카드 상태 ('new' | 'learning' | 'review' | 'relearning')
  stability: number; // 기억 안정성 (단위: 일)
  difficulty: number; // 카드 난이도 (FSRS 척도)
  interval: number; // 다음 복습까지의 간격 (단위: 일수 또는 분)
  repetitions: number; // 연속 성공 횟수
  lapses: number; // 복습 카드의 실패 횟수
  dueDate: string; // 다음 복습 예정 일시 (ISO Date String)
  lastReviewedAt?: string; // 마지막으로 학습한 일시

  createdAt: string; // 생성일
}

// 덱 (Deck) 모델
export interface Deck {
  id: string; // 고유 ID
  userId: string; // 소유자 ID (User.id)
  title: string; // 덱 이름 (예: JLPT N5 필수 단어)
  description?: string; // 덱 설명
  category: string; // 카테고리 (예: 동사, 명사, 표현)
  cards: Card[]; // 덱에 포함된 카드 리스트
  createdAt: string;
  updatedAt: string;
}
```

## 5. UI/UX 화면 구조 및 흐름 (User Interface & Flow)

### 5.1 화면 구조 (Screens)

1. **로그인 화면 (Login Screen)**
   - 사용자명, 비밀번호 입력 필드
   - 로그인 버튼
2. **홈 화면 (Deck List Screen)**
   - 전체 덱 목록 카드 노출 (오늘 학습 예정 카드 수: New/Learning/Review 구분)
   - '새 덱 추가' 버튼
   - 상단 오른쪽: 현재 사용자 정보 및 로그아웃 버튼
3. **덱 상세 / 단어 관리 화면 (Deck Detail & Word List Screen)**
   - 단어 리스트 표시
   - 각 단어 행에 편집/삭제 버튼
   - '새 카드 추가' 버튼
   - '학습 시작' 대형 버튼
4. **단어 생성 페이지 (Word Create Page)**
   - 단어(일본어 표기), 읽기(Reading), 뜻(Meaning), 품사(Part of Speech) 입력 가능
   - 예문 리스트 입력 영역 (각 예문과 해당 한글 뜻을 개별적으로 추가/삭제/수정 가능)
   - 저장 및 취소 버튼
5. **단어 편집 페이지 (Word Edit Page)**
   - 기존 카드 정보를 모두 불러와 수정 가능
   - 단어, 읽기, 뜻, 품사, 예문 리스트 전체 수정 가능
   - 변경 사항 감지 시 저장 버튼 활성화
   - 저장 및 취소 버튼
6. **학습 화면 (Flashcard Screen)**
   - 상단: 진행도 프로그레스 바 및 해당 덱의 남은 카드 수
   - 중앙: 플래시카드 (터치/클릭 시 3D Flip 애니메이션)
   - 하단: **Anki 4단계 평가 버튼 (`Again`, `Hard`, `Good`, `Easy`)** + 예상 복습 주기 텍스트

### 5.2 주요 동작 흐름 (Workflows)

#### 단어 생성 워크플로우

1. 사용자가 덱 상세 화면에서 '새 카드 추가' 버튼 클릭
2. 단어 생성 페이지로 이동
3. 사용자가 단어, 읽기, 뜻, 품사, 예문 정보를 입력
4. 저장 버튼 클릭
5. Supabase DB에 새 카드 저장
6. 덱 상세 화면으로 돌아가기

#### 단어 편집 워크플로우

1. 사용자가 덱 상세 화면에서 단어 행의 편집 버튼 클릭
2. 단어 편집 페이지로 이동 (현재 정보 미리 로드)
3. 사용자가 필드 수정 (예: 뜻 변경)
4. 저장 버튼 클릭
5. 백엔드가 변경 사항 감지 및 처리:
   - **뜻(meaning) 필드 변경 감지 시:**
     - 카드의 현재 `state` 확인
     - `state === 'review'` 인 경우 → `'relearning'` 으로 전환
     - 다른 상태 (`new`, `learning`, `relearning`) → 상태 유지
   - **기타 필드 변경** (읽기, 품사, 예문 등) → 상태 유지
6. 백엔드 DB에 변경 사항 저장
7. 덱 상세 화면으로 돌아가기

## 6. 비기능적 요구사항 (Non-Functional Requirements)

- **성능 및 응답성:** 카드 뒤집기 애니메이션은 60fps로 부드럽게 동작하며, 백엔드 DB와의 효율적인 데이터 통신으로 빠른 응답 제공.
- **접근성 및 반응형:** 모바일 화면(폭 360px 이상)부터 데스크톱 화면까지 레이아웃 파손 없이 대응.
